# IOTProject 项目功能说明

本文档基于当前仓库代码梳理：**物联网设备管理后端**，采用 Go + Gin，配合 PostgreSQL、Redis，提供 HTTP API、设备数据上报、策略与告警、WebSocket 实时推送。

---

## 一、项目定位

为物联网场景提供统一后端能力：用户账号与登录态、设备绑定与列表、传感器数据存储与历史查询、基于阈值的自动化策略（告警 / 下行控制）、以及面向 Web/App 与硬件的 WebSocket 通道。

---

## 二、技术架构

| 层级 | 说明 |
|------|------|
| **入口** | `cmd/server/main.go`：初始化 `app.App`，监听系统信号退出 |
| **应用组装** | `internal/app/app.go`：GORM、Redis、仓储、服务、WebSocket Hub、路由 |
| **传输层** | `internal/transport/http`：Gin Handler；`internal/transport/middleware`：JWT、统一错误 |
| **业务层** | `internal/service`：用户、设备、设备数据、设备策略 |
| **持久层** | `internal/repository/postgres` |
| **领域模型** | `internal/domain` |
| **实时通信** | `internal/websocket`：Hub、用户客户端、设备客户端、事件广播 |

**依赖组件**

- **PostgreSQL**：用户、设备、传感器数据、策略、告警日志等（GORM）。
- **Redis**：登录 Token 集合（会话校验）、分布式锁（注册防刷）、策略告警防抖、验证码等。
- **静态资源**：`./static` 映射到 HTTP `/static`（含头像上传目录）。

## 三、功能模块概览

### 1. 用户与认证

- **注册**：用户名、手机、邮箱；密码强度校验；**图形验证码**（需 `device_id`、`captcha_id`、`code`）；多字段 **Redis 分布式锁** 防并发重复注册。
- **登录**：支持用户名 / 手机 / 邮箱作为 `identity`；同样需要验证码；成功后签发 **JWT**（约 3 天有效），Token 记入 Redis 集合 `auth:tokens:{user_id}`。
- **鉴权**：受保护接口校验 `Authorization: Bearer <token>`，且 Token 必须在 Redis 集合中（登出即移除，等效于失效）。
- **登出**：从 Redis 移除当前 Token（公开路径 `POST /user/Logout` 与鉴权路径 `POST /user/logout` 均存在）。
- **资料与密码**：更新资料、修改密码（鉴权）；**重置密码**（通过身份信息验证，无需登录）。
- **用户信息**：`GET /user/info` 返回 `UserVO`（含 `role_id` 等）。
- **头像**：`POST /user/uploadavatar` 表单上传，校验图片类型与尺寸，保存至 `static/uploads/`。

**说明**：数据模型含 `role_id`，中间件会把角色写入 Context 与 Redis 缓存；**当前路由中未见单独的管理员专用 HTTP 接口**（若需后台管理能力需另行扩展路由与权限校验）。

---

### 2. 设备管理（需登录）

- **绑定设备**：`device_uid` + `device_name`；绑定成功后通过 WebSocket Hub 发布 `bind` 事件。
- **解绑设备**：发布 `unbind` 事件。
- **修改设备名称**。
- **获取当前用户设备列表**（`GetDevicesInfo`）。

设备在库中有状态、最后在线时间等字段；解绑后 `user_id` 可为空，后续数据上报仍会入库，但策略引擎会跳过未绑定用户的设备逻辑。

---

### 3. 设备数据（传感器）

- **上报数据（无需 JWT）**：`POST /devicedata/uploaddata`  
  便于硬件或网关直接上报。载荷为 `DeviceData`：温度、湿度、光照、噪声、火焰、一氧化碳、风扇/灯光/RGB 等，以及 `device_uid`。
- **处理流程**：持久化 → 异步 **策略引擎** → 若设备已绑定用户，向该用户 WebSocket 推送 `device_update` 类型消息。

- **历史查询（需登录）**：`GET /devicedata/history`  
  查询参数含 `device_uid`、`sensor_type`（合法别名：`temp`、`humi`、`light`、`noise`、`fire`、`Co`）、`limit`。会校验设备归属，防止越权。

---

### 4. 设备策略与告警（需登录）

用户可为设备配置策略：**传感器类型、比较运算符、阈值、动作类型**。

- **动作类型**（`action_type`）：`alert`（仅告警）、`control`（仅控制）、`both`（告警 + 控制）。
- **策略 CRUD**：创建、按设备查询、删除；创建/删除时会向对应用户推送 WebSocket 事件（如 `policy_create`、`policy_delete`）。
- **告警**：策略触发后写入告警日志，支持 **未读数量**、**待处理列表**、**标记已处理**（`PUT /devicepolicy/markaler/:log_id`）；处理后可推送 `alert_handled` 事件。
- **防抖**：告警路径使用 Redis 控制短时间内的重复触发，减轻刷屏与数据库压力。

策略引擎在每次设备数据保存后异步执行，按设备拉取策略并匹配当前传感器值。

---

### 5. WebSocket

| 路径 | 用途 |
|------|------|
| `GET /ws` | Web/App 客户端连接（代码中先建立连接，具体鉴权与 userID 绑定逻辑见 `Client` 读写协程） |
| `GET /ws/device` | **硬件设备**长连接；查询参数 `device_uid`、`token` |

**设备接入鉴权**：`token` 为 `MD5(device_uid + "23wlw4IOT")` 的十六进制字符串（与 `validateDevice` 一致）；生产环境应在 `CheckOrigin`、密钥等方面加固。

Hub 负责注册用户连接、设备连接、按用户推送消息、广播业务事件等。

---

### 6. 安全与限流

- **登录限流**：`/user/login` 使用 Redis + Lua 的限流中间件（例如每分钟 5 次，见 `router`）。
- **密码**：注册/修改等使用项目内密码哈希（与 bcrypt 相关依赖并存，以实际 `crypto` 包实现为准）。
- **CORS**：允许所有来源（开发友好，生产建议收紧）。

## 四、HTTP API 一览（与代码一致）

前缀均为服务根路径（默认端口见环境变量 `SERVER_PORT`，默认 `8888`）。

**用户**

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/user/register` | 否 | 注册 |
| POST | `/user/login` | 否 | 登录（限流） |
| POST | `/user/resetpassword` | 否 | 重置密码 |
| POST | `/user/Logout` | 否 | 登出（读 Authorization） |
| GET | `/user/GetCaptcha` | 否 | 获取验证码 |
| POST | `/user/update` | 是 | 更新资料 |
| POST | `/user/changepassword` | 是 | 修改密码 |
| GET | `/user/info` | 是 | 当前用户信息 |
| POST | `/user/logout` | 是 | 登出 |
| POST | `/user/uploadavatar` | 是 | 上传头像 |

**设备**

| 方法 | 路径 | 鉴权 |
|------|------|------|
| POST | `/device/bindDevice` | 是 |
| POST | `/device/unbindDevice` | 是 |
| POST | `/device/updatedevicename` | 是 |
| GET | `/device/getDevicesInfo` | 是 |

**设备数据**

| 方法 | 路径 | 鉴权 |
|------|------|------|
| POST | `/devicedata/uploaddata` | 否 |
| GET | `/devicedata/history` | 是 |

**策略与告警**

| 方法 | 路径 | 鉴权 |
|------|------|------|
| POST | `/devicepolicy/createpolicy` | 是 |
| GET | `/devicepolicy/getepolicy` | 是（query: `device_uid`） |
| POST | `/devicepolicy/deleteepolicy` | 是 |
| GET | `/devicepolicy/getunreadcount` | 是 |
| GET | `/devicepolicy/getpendingaler` | 是 |
| PUT | `/devicepolicy/markaler/:log_id` | 是 |

**WebSocket**

| 方法 | 路径 |
|------|------|
| GET | `/ws` |
| GET | `/ws/device` |
